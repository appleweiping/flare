# Independent audit of the recovered FLARE UQ work

Audit scope: code and documentation at `7bf56a647c9ab0f1a845fbe9220881a0bbf5474c`, recovered from `appleweiping/flare:uq-conditional-calibration`. Read-only inspection; no sealed prediction arrays, test arrays, selection experiments, or model fitting were performed. References are repository-relative line numbers at that commit. This review distinguishes unsupported theoretical claims from demonstrated numerical defects.

## What the existing work established

The project already has useful, substantially investigated UQ results: major conditional coverage deficits despite approximately nominal marginal coverage; context missingness and photometry-density stress tests; energy-stratified alternatives; a measured fold/refit score-scale mismatch; nested cross-fitting; and explicit negative adoption decisions for inefficient candidates. The study reports that the test set has been consumed and labels later designs as exploratory (`docs/uq_preregistration.md:132–167`; `docs/uq_conditional_calibration.md:187–198`). Preserve these disclosures.

Architecturally, the six-class hierarchy maps five top-level classes plus an SLSN branch to probabilities. Class prediction sets, anomaly evidence, and rule-based follow-up are different layers. `flare.consensus` normalizes multiple LUNA scorers and computes known-population rank p-values, optionally by detection-count strata (`flare/consensus.py:31–71`). `flare.lifetime` replays scheduled prefixes to quantify an empirical source-level alarm rate. `flare.skyportal` makes the final triage decision. An uncertainty improvement should specify which layer and which error event it controls.

## Highest-priority findings

### 1. Model-matched cross-conformal ranks are not an exact conformal guarantee

`scripts/uq_study/nested_eval.py:84–131` compares each held-out calibration score with a query scored by the same inner model, which fixes the obvious cross-model scale mismatch. It then pools counts over models into `(1 + sum counts)/(1 + sum calibration sizes)` and thresholds at alpha. That is a cross-conformal construction; it is not generally an exactly superuniform p-value under arbitrary dependence between folds. Merely calling it “proper” does not give split-conformal's finite-sample guarantee. `docs/uq_preregistration.md:154–157` must not be read as a theorem or as an implementation of CV+/jackknife+; those constructions and guarantees differ.

The deployed baseline is weaker still: `scripts/train_full_cc.py:42–76` calibrates on fold-model scores and exports a refitted model; `scripts/uq_study/oof.py:62–80` repeats that construction. The scale mismatch is honestly acknowledged by the study. A new formal method must construct a valid per-model object-level p/e-value and use a proven merger, not rename pooled ranks.

### 2. The API promises a guarantee that the fitted construction does not establish

`flare/hierarchical.py:271–299` describes `guaranteed_error` as a guarantee and returns `guaranteed_error=alpha` unconditionally, including the pooled-OOF/refit baseline and atypicality mode. Neither the cross-fit/refit mismatch nor empirically fitted context-augmented strata establish that exact bound. This is a communication/semantics defect independent of whether empirical coverage happens to be near 90%.

A sound replacement should distinguish `target_miscoverage`, measured coverage, mathematical guarantee type, assumptions, and the calibration population. Do not silently change public semantics as part of a research prototype; specify and test them before production adoption.

### 3. Lifetime correction does not cover the full anomaly-review decision

`flare/lifetime.py:8–21` correctly states that the minimum of successive p-values is not anytime-valid and that the exported FAR is empirical and schedule/population specific. The reference is built using the same known objects both for per-index ranks and final lifetime calibration (`scripts/export_lifetime_far.py:41–72`); the file explicitly admits in-sample reference rates. This is not a new formal anytime-valid baseline.

The operational composition is important: `flare/skyportal.py:292–306` replaces the anomaly branch with the lifetime alarm, then sends objects to `anomaly_review` if **either** that alarm **or** the separate `review_trigger` fires. The latter has a per-analysis target, not a lifetime guarantee. Therefore “one false alarm per week” for the lifetime branch cannot be attributed to the combined review queue. Repeated testing of the review trigger is uncorrected by that lifetime mechanism. The stellar/host-mismatch priority gates further mean primitive alarm events and final actions need separate metrics.

### 4. The current trigger is a useful load-control policy, not a demonstrated new ranking method

The old conformal trigger is algebraically `p_predicted <= 0.1`; T1 lowers the threshold on the same statistic (`scripts/uq_study/methods/t1_trigger.py:3–20`). The reported approximately 3.5x improvement is against randomly thinning the old boolean rule, not against optimally thresholding the same ranking at equal FAR (`docs/uq_conditional_calibration.md:159–185`; `t1_trigger.py:29–37,310–335`). A ranking-based comparator using the same score would trace the same ROC. Report review-load reduction and observed recall honestly; do not claim discrimination improvement from a threshold change alone.

Additionally, the export docstring says the threshold is against existing shipped class scores (`scripts/export_review_threshold.py:9–11`), but `review_threshold` recomputes its own score lists from newly cross-fitted probabilities (`:42–56`), and the old `conformal.json` is read only after tau is obtained (`:107–109`). Existing documentation acknowledges recipe-versus-original-fit mismatch, but the exported 1% remains a nominal empirical target. The leave-one-out second-stage p-value ranking in `t1_trigger.py:15–20` also needs a theorem; removal of each object's own score does not by itself establish joint exchangeability with a new object's differently computed score.

### 5. Equal object weights do not automatically validate context augmentation or learned cells

`flare/atypical.py:71–97` computes energy edges from calibration objects, creates multiple context views, and calibrates weighted within-class/cell quantiles on those same objects. Per-object weights correct gross pseudoreplication, but do not alone prove validity for an arbitrary deployment missingness pattern. The hierarchy theorem requires an appropriate exchangeable cluster/test sampling model; selected deterministic/mixed context views must match that model. Calibrating edges on the calibration set also breaks the simplest fixed-partition Mondrian argument. A formal route needs independently learned partitions or a justified symmetric construction, plus an explicit target distribution over missing-context patterns.

## Evaluation and provenance risks

- **Initial leave-one-fold-out evaluation is not a clean outer holdout for the entire calibrator.** `harness.py:161–178` uses other folds' OOF predictions as calibration data, but the models creating those scores were trained using objects in the evaluated fold. Nested calibration (`nested.py:43–59`) removes this leakage path at the outer level and is the preferable development protocol. It still does not automatically validate the specific inner p-value merger.
- **U is unstable and omits small rare-class cells.** `harness.py:138–157` maximizes coverage deficit only over cells with >=30 evaluation objects. `:223–243` applies the >=30 cutoff anew inside each bootstrap draw and holds predictions/calibration thresholds fixed. This non-smooth endpoint and variable inclusion should not be the sole success criterion. Add per-class/group intervals, fixed eligible-cell definitions, calibration-refit variability, and prespecified utility or set-size/coverage trade-off curves.
- **Nested strata differ from the original registration.** `nested_eval.py:61–67` computes nobs terciles and energy quintiles on the evaluated outer fold. This is label-free and method-independent but batch-defined, not the original calibration-defined population groups. Report it explicitly and retain fixed-partition sensitivity checks.
- **Horizon cohorts must be joined by object IDs.** `build_cache.py:54–65,84–94` independently drops objects whose features raise ValueError at each horizon. `oof.py:59` and `nested.py:41` regenerate folds from the available rows. If eligibility differs across horizons, row indices/fold IDs cannot be assumed aligned for a sequential study. Freeze a master object assignment; define missing/insufficient-data looks prospectively.
- **Feature extraction preserves useful causal boundaries.** `build_cache.py:54–61` truncates events and calls inference-path feature extraction; thinning restarts the detection clock (`:34–46`). Keep this. Future replay must additionally freeze context at each historical look; reusing later available context can leak future information even when light-curve features are causal.
- **Saved training artifacts are insufficient for exact recovery of the claimed latest work.** `oof.py:62–72` saves only the final model, not each fold model. `nested.py:48–59` saves predictions but no inner/final fold models, source hashes, data hashes, dependency manifest, or completion sentinel. The recovered branch has nested result JSON only for h100 and h20 and no `fold_test_preds.py`. No `paper_data` cache directory exists in this checkout at audit time. Claude's later h5/h10 nested runs and fold-model test/anomaly arrays are not established by this branch. Verify recovery externally or explicitly regenerate with provenance; never fabricate their completion.
- **Test contamination persists after sealing.** Previously inspected benchmark test objects remain development/descriptive data even if new predictions are written under `sealed/`. A newly named directory does not restore a confirmatory holdout (`docs/uq_preregistration.md:145–147`). New spectroscopic objects, a genuinely unused time cohort, or another untouched population are needed for confirmatory claims.

## Mathematical audit of the proposed e-value continuation

The outline can support a sound conservative method, but only with explicit conditions:

1. For each fixed model k and prespecified look h, calibration objects and the new known object must be exchangeable under the same scoring function, conditional on everything used to train/tune that model. A model being unfitted on those objects is necessary, not sufficient when score parameters/partitions/weights were tuned on them.
2. A simple independently valid construction is a conservative rank p-value, transformed by a prespecified decreasing p-to-e calibrator g with integral on [0,1] <=1. For example `g(p)=epsilon*p**(epsilon-1)` for fixed 0<epsilon<1. A more powerful direct conformal e-value construction may be possible, but must be stated/proved specifically.
3. Fixed nonnegative model weights summing to <=1 preserve E[e]<=1 under arbitrary dependence. Choosing weights based on the same object's evidence is not justified by that argument.
4. With fixed nonnegative horizon weights summing to <=1, `E_t=sum_{h observed by t} w_h e_h` is pathwise bounded by `E_total=sum_h w_h e_h`; hence E[E_T]<=1 for any stopping time under any filtration, assuming each unconditional e_h is valid and the horizon/eligibility policy is properly defined. This establishes a domination-based anytime-valid evidence process; it need not be a test supermartingale. It is not the usual product of conditional e-factors. Include no-augmentation and strict split baselines to diagnose validity.
5. Distinguish hypotheses. Class-conditional e-values test `Y=c`; they do not become known-population OOD e-values by selecting the predicted class. For the composite known-class null, a minimum across valid class-null e-values is conservative; alternatively calibrate a fixed anomaly statistic directly on a representative known population. A maximum or a predicted-class choice is not automatically valid.
6. e-BH controls FDR for a prespecified family of valid null e-values without an independence assumption. Adaptive prefiltering, repeatedly accumulating discoveries across batches, and a changing denominator require their own argument. FDR is not FAR, not a per-week false-alarm count, and not conditional coverage.
7. Four looks and five folds spread evidence; rare-class rank discreteness and class-union minima may eliminate power. This is the main empirical risk, not proof of improvement. Fix the design and compare to strong matched-budget baselines before selecting variants.

## Recommended next study

Study a model-matched, object-level **sequential triage** layer rather than another energy-bin recalibration paper. Its question is whether FLARE can control the lifetime probability or discovery error of costly review decisions while preserving early rare-object yield. Keep classifiers and existing production defaults frozen.

First specify the null, operational unit, allowed looks, eligibility/context policy, model/calibration ownership, weights and evidence mapping. Build exact tests on finite rank distributions, ties, dependent looks, missing looks, and adaptive stopping; confirm data/model provenance before any scoring. Compare (a) current per-look trigger, (b) calibrated lifetime replay on an independent calibration sample, (c) alpha-spending/Bonferroni over the same looks, (d) valid merged p-values or a fixed single-split method, and (e) the e-value candidate. Evaluate source-level false alarms, rare-object recall, detection delay, review workload, and computational cost; use matched workload and matched nominal error comparisons. Retain class-set coverage as a separate secondary task.

Use nested development folds for engineering and power estimation, explicitly exploratory because this public benchmark has already shaped the project. Freeze all design choices before a prospective or external validation. A publishable contribution would require either a new useful theorem/design beyond standard e-merging, or compelling external astronomical utility plus a reproducible deployment study. The generic combination “average e-values + fixed look weights + e-BH” alone is established machinery, not sufficient novelty.
